# content script 用声明式注入，范围是所有站点

字幕浮层由 `manifest.json` 里声明的 content script 渲染，`matches` 是 `<all_urls>`。

## 为什么不限定 tiktok.com

TikTok 直播是主要场景，但西语直播散落在很多平台上，把工具钉死在一个域名上没有道理——底层能力（`tabCapture` + ASR + 翻译）本来就是通用的。

代价是安装时的权限提示从「读取和更改你在 tiktok.com 上的数据」变成「**读取和更改你在所有网站上的数据**」。考虑到使用者是作者和少数几个知情的朋友（ADR-0003），这个提示可以靠口头说明消化掉；换成公开分发就要重新权衡。

## 为什么不用 `chrome.scripting` 按需注入

`activeTab` 权限能在用户点击扩展图标时临时授予当前标签页的访问权，做到**零 host 权限、零安装警告**，一度是最干净的选项。

但 `activeTab` 的授权**在页面硬导航后失效**，而且无法自动恢复——用户换个直播间或刷新一下，字幕就没了，必须重新点扩展图标。用一次性的安装提示，换掉一个每天都会遇到的摩擦，这笔账是划算的。

声明式注入还白拿一个好处：硬导航后 Chrome 会自动重新注入 content script，不需要监听 `tabs.onUpdated` 自己补。

## 后果

- content script 会在**每一个**页面上加载，所以它必须能极快地判断「当前没在给这个标签页做字幕」并立即退出，不做任何 DOM 操作。
- content script 加载时要主动向 background 握手询问当前捕获状态。它可能是在捕获进行中被重新注入的（硬导航），对状态一无所知；这是状态恢复的关键路径，不是可选优化。
- `<all_urls>` 已经覆盖 `activeTab` 的能力，manifest 里的 `activeTab` 可以去掉。
