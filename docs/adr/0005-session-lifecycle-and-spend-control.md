# 长静音自动断连，并用会话时长上限做花钱保险丝

AssemblyAI 流式转写按 **WebSocket 打开时长**计费（$0.45/小时），不按发送的音频量。主播沉默、用户离开、忘记关闭——全都在照常计费。所以会话生命周期是个花钱问题，不只是资源问题。

我们的策略有三层：

1. **长静音断连**：连续 60 秒未检测到语音就关闭 WebSocket；重新有声音时换新 token 重连。
2. **会话硬上限**：换 token 时指定 `max_session_duration_seconds = 3600`，把单次「忘记关闭」事故的损失钉在 $0.45。
3. **显式的手动停止**：用户随时能主动结束，不依赖任何自动机制。

## 为什么阈值是 60 秒而不是更激进

自然停顿只有 1–3 秒。每个停顿都断开的话，省不到钱，反而因为重连要换 token + 握手（约 1 秒）而吃掉每句话开头的几个字。60 秒的阈值只会命中真正的钱坑：主播离席、插广告、用户开着标签页去做别的事。

重连仍然会丢重新开口时的头几个字。缓解办法是在 AudioWorklet 里留一个约 2 秒的环形预缓冲，重连成功后先冲进去。RMS 本来就要在 worklet 里逐样本算（静音检测靠它），这个缓冲几乎是白送的。

## 关于「临时 Token」的一个澄清

浏览器的 WebSocket 不能自定义 `Authorization` header，所以必须先用 API Key 换一个一次性 token（`GET /v3/token`，`expires_in_seconds` 上限 600），再把 token 拼进 WebSocket URL。

**这在本项目里纯粹是绕开 Web 标准限制的技术手段，不是安全机制。** 临时 token 的设计意图是「服务端持有 Key、客户端看不到 Key」，但我们没有服务端——Key 就在扩展的 `storage.local` 里，换 token 也是扩展自己做的。真正在做安全工作的是「每人填自己的 Key」（见 ADR-0003）。不要因为用了 temporary token 就以为 Key 被保护了。

Token 是一次性的、只能用于一个 session，所以每次重连都要重新换。Token 只在连接那一刻需要有效，连上之后过期不会踢掉会话。

## 后果

- 会话状态机比「开/关」多两个态：`idle`（静音断开中，音频仍在采集，等待声音）和 `reconnecting`。
- 捕获跑满 1 小时会被服务端强制结束。这是**故意的**——想继续看就再点一次开始，这点摩擦换的是花钱有上限。
- **意外断连必须先分类错误再决定重不重连。** 这是本决策里最容易写出来的花钱 bug：每次重连都是一次新会话、都在计费，所以鉴权类错误（Key 失效、余额耗尽）必须立即停止并报错，只有网络类错误才重试。重试上限 5 次指数退避（约 30 秒），够扛过大多数网络抖动，同时保证即使漏判了某种错误也不会无限循环。注意这跟上面的长静音断连是两条路径——那个是计划内的，这个是意外。
- track 的 `ended` 事件（用户关掉被捕获的标签页）必须触发完整停止并关闭 WebSocket，不能只打日志。否则就是在为一个已经不存在的标签页付钱。
