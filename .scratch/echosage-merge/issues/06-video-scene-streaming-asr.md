# 06 — 视频字幕场景流式转写、单轮转写停止、播放进度采样层

**What to build:** 没有原生字幕的 TikTok 视频，现在也能有字幕了——音频通过 AssemblyAI 流式转写出来，译文按当前引擎产出。这段转写在视频**播完一轮**之后自动停止定稿：TikTok 视频默认循环播放，不做这件事就会对着同一段音频反复转写、反复计费。

**Blocked by:** 02（视频场景存在）, 04（源语言可配置——视频内容常常不是西语）, 05（引擎与翻译时机已确立，流式产出的单位可以直接接上）

**Status:** resolved

这一票还要建立**播放进度采样层**——由 content script 采样播放进度、喂给 `core/` 里的纯函数做判定。票 07 的"跟随播放"和票 08 的悬浮层进度同步都复用这一层，不要各造一套。

- [x] 没有原生字幕轨的视频会走 AssemblyAI 流式转写，产出与直播场景同构的单位
- [x] 「切换到新视频时」**两档**（手动 / 自动）：手动档只有点击才开始；自动档切到无原生字幕的视频就自动开始。**没有第三档**——即时翻译下转写和翻译是同一条流水线，"获取但不翻译"不做（ADR-0009、spec Out of Scope）
- [x] 自动档的费用提示文案按实际行为改写，不要沿用设计稿里"自动录制 30 秒标签页音频"的旧说法
- [x] 视频播完一轮后自动停止定稿，继续循环播放不会重复转写
- [x] `core/` 新增"单轮转写"判定纯函数：输入播放进度采样序列，输出是否已完成一轮；不直接读 DOM。测试覆盖临播完、循环回跳、暂停不动、拖进度条跳跃
- [x] 播放进度采样做成可复用模块，07/08 直接使用
- [x] 长静音断连与会话硬上限（ADR-0005）与单轮停止并存，任一先触发即停止
- [x] 与直播场景的会话相互独立：两个标签页可以同时各跑一条流式会话，不设跨标签页全局并发上限

## Answer

无原生字幕的视频可按手动或自动模式建立独立的 AssemblyAI 流式会话。`core/playback.js` 用纯函数识别自然播放到结尾后的循环回跳，并被侧边栏和视频悬浮层共同使用；暂停和拖动不会误触发停止。
