# 05 — 视频字幕场景的翻译引擎（两个选项，且只属于这个场景）

**What to build:** 视频字幕的翻译引擎设置从合并前的"AI 模型 / 微软"变成"Chrome 内置 nano（默认）/ AI 模型"。选 Chrome 内置时，字幕在本地逐个单位翻出来；选 AI 模型时，等整段文本齐了再一次性发给已配置的聊天接口换回整段译文。直播实时场景**不提供这个选择**，永远走本地翻译。

**Blocked by:** 02（视频场景存在）, 03（设置分区存在）, 04（原生字幕常常不是西语，引擎要能按所选语言工作）

**Status:** resolved

术语按 `CONTEXT.md`：**即时翻译**（Chrome 内置：单位一定稿就翻）与**整段批量翻译**（AI 模型）是"翻译引擎"这个轴；它和 ADR-0007 的"译文触发时机"（停顿/句子，决定什么算一个单位）是**两个正交的轴**，不要揉进同一个条件判断。

- [x] 视频字幕分区出现引擎选择器，两个选项，默认 Chrome 内置 nano
- [x] 原生 WebVTT 字幕在两种引擎下都能正确译出并展示
- [x] 「直播实时」场景仍然没有引擎选择器，且代码里不存在让直播走 AI 模型的路径（ADR-0003 + ADR-0008）
- [x] `core/session.js` 新增引擎轴的状态分叉，挂在既有 `pause`/`sentence` 轴的**下游**；测试覆盖两个轴的组合
- [x] 会话进行中切换引擎，只影响此后定稿的单位——已经翻好的保持原样，允许一段字幕里两种引擎的译文共存；不清空重翻，不禁用开关
- [x] 上一条用事件序列测试断言：翻两句 → 切引擎 → 再两句 → 结束，最终状态里前两句是本地译文、后两句走批量路径
- [x] AI 模型翻译进行中，译文轨留空或标"翻译中"，不显示半成品

## Answer

视频设置提供本地即时翻译和 AI 整段批量翻译。会话 reducer 把引擎作为触发时机的下游轴，保留既有译文并只把切换后的单位纳入 AI 批次；对应事件序列已由核心测试覆盖。
