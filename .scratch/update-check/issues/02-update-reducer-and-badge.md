# 02 — 更新状态机与角标（发现可用更新）

**What to build:** 扩展自己定期去问 GitHub 最新的**发布版本**是什么，和自己的**运行版本**比。发布版本更高时，工具栏图标上的角标亮起来；用户完成更新、运行版本追上之后，角标自己消失。断网或 GitHub 抽风时安静无事发生，不打扰用户。

这一票只做**发现**，不做任何呈现界面——用户此时只能看到角标。呈现在 03。

这是本仓库 service worker 里的**第一个 reducer 宿主**（既有的会话状态机跑在离屏文档里）。派发指令并逐条执行的形状照抄离屏文档里那几行，不要为它抽公共层。事件与指令的完整清单见 `.scratch/update-check/spec.md`「单一测试 seam」一节——那是这个决定的精确形式，照着实现。

**Blocked by:** 01（需要远端真的存在 Release，否则端点返回 404，无从验证）

**Status:** ready-for-agent

- [ ] 新增更新状态机纯逻辑模块，形如既有会话状态机：接受状态与事件，返回新状态与指令列表；不经过 bundler，由 Node 内置 test runner 直接导入（ADR-0010）
- [ ] 版本解析容忍 `v` 前缀与位数不等（`1.2` 视同 `1.2.0`）；带预发布后缀的版本一律不构成可用更新
- [ ] **严格大于**才构成可用更新：相等不提醒，发布版本更旧也不提醒（覆盖作者回滚与开发机超前两种情形）
- [ ] 持久化的只有发布版本、它的 Release 链接、上次检查时间——**不存已读状态，不存"有更新"这个布尔值**
- [ ] 宿主启动时用缓存的发布版本立即重算角标，**不发起网络请求**；仅当距上次检查超过 24 小时才额外发起一次检查
- [ ] 定时检查周期 24 小时；扩展清单新增定时器权限
- [ ] 请求走仓库的 Release 接口，未认证；既有的全站主机权限已覆盖该域名，不新增主机权限
- [ ] 定时触发的检查失败后静默丢弃：不更新上次检查时间、不改角标、不产生任何面向用户的错误
- [ ] 检查进行中重复触发不会发出第二次请求
- [ ] 角标文案简短（一个计数或圆点即可）并带可辨识的背景色；可用更新不成立时角标被清除
- [ ] 状态机测试覆盖上述每一条行为，风格与既有会话状态机测试一致：构造状态 → 派发事件 → 断言状态与指令，不 mock 任何浏览器全局对象
- [ ] service worker 与任何界面文件中不含版本比较或"是否该检查"的判定分支——它们只负责执行指令
- [ ] 手工验收：把运行版本临时调低，角标在一次检查后亮起；调回与发布版本相等，重载后角标消失
