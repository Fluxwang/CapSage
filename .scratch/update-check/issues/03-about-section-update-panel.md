# 03 — 关于分区的更新面板

**What to build:** 用户顺着角标点进设置页的关于分区，在那里看懂自己的处境并完成更新：看到运行版本与发布版本的对照，可以主动点一下检查，看到"先跑脚本拉取、再点按钮重载"的两步说明，然后点一个按钮让新代码真正生效——不必再跑一趟扩展管理页找刷新按钮。

**这一票的成败在文案。** 用户跑完更新脚本时磁盘上已是新代码，但运行版本没变，**角标还在**。如果界面只说"运行脚本即可更新"，用户会以为脚本失败了，反复运行直到放弃。拉取与重载必须被讲成两件有先后的事，并说清角标要等第二步之后才会消失。

规格见 `.scratch/update-check/spec.md`「关于分区」一节，词汇以 `CONTEXT.md`「更新」一节为准。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 关于分区显示运行版本与发布版本的对照；从未成功检查过时，发布版本一栏不显示占位假值
- [ ] 一个三态按钮：检查更新 / 检查中 / 发现新版本，三态的文案与可点击性各自正确
- [ ] 用户主动点击触发的检查失败时**显示错误提示**（与定时检查的静默失败形成对比）；提示不长驻，下次检查即覆盖
- [ ] 可用更新成立时展开两步说明：第一步指明到仓库根目录运行更新脚本完成拉取，第二步点下面的按钮完成重载
- [ ] 说明里明确写出角标会在重载之后消失，而不是拉取之后
- [ ] 「我已拉取，重载扩展」按钮触发扩展重载，使磁盘上的新代码生效；按钮附近预告该操作会关闭当前设置页
- [ ] 正在捕获时该按钮置灰并说明原因（重载会中断正在进行的捕获，当前字幕会丢）；捕获状态经既有的离屏状态查询取得，作为事件喂进状态机，界面不自行判断
- [ ] 停止捕获后按钮在不刷新设置页的情况下恢复可用
- [ ] 按钮态、文案、是否置灰全部由状态机的派生视图给出，设置页不做任何推导
- [ ] 状态机新增的重载与捕获状态相关行为有对应测试：捕获中收到重载请求不产生重载指令；空闲时产生；捕获状态变化正确翻转按钮态
- [ ] 视觉风格与关于分区既有的版本行、说明文字、链接行保持一致，不引入新的视觉语言
